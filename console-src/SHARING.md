# 社区提交与待审池

用户在发起本次测评时可以勾选共享. 共享默认关闭. 配置了发布方的接收地址后, 运行正常结束并生成评分文件时自动发送. 全部任务有科学终态或仍有技术缺口的正常结束都可提交. 技术缺口的分数保留为空, 严格核验通过数可以为零.

每份提交包含精确模型ID, harness名称和版本, 测评协议, 所选题号及题目哈希, 运行预算, 逐题和分组成绩摘要, 评分规则及证明规范的哈希. 对每个所选严格核验结果, 附上核验所用的`f.state`和`Candidate.lean`原始字节及绑定哈希. 两个文件按Base64写入JSON以保留原始换行和编码. 本地导出核对评分所选试次, 成果文件, 核验收据和能量报告的绑定. API地址, API key, 环境变量, 本地路径字段, 原始对话及日志仅留在本机. 导出会检查传入的API key字面值及已知私有地址是否出现在共享内容中, 命中时阻止发送.

并行运行的提交额外记录题目并行数和每题分配的CPU数. 接收器兼容此前的`f.py`证书和串行提交. 旧接收器需更新后才能接收新的`f.state`证书.

## 发布方部署

在发布方控制的机器上准备启用TLS的域名, 一个可持久化的私有目录, 以及Python 3.10或以上. 在控制台目录运行以下命令, 将数据库放在Web文件目录之外.

```bash
mkdir -m 700 ./private-intake
python3 receiver.py --db ./private-intake/pending.sqlite3 --port 8766
```

将外部HTTPS的`POST /v1/submissions`代理到`127.0.0.1:8766/v1/submissions`, 保留`Content-Type`, `Content-Length`和`Idempotency-Key`请求头. 代理只需开放这一条路由. 按服务规模分配磁盘和限制请求速率, 同时允许最长上传的请求体. 接收器按最多50道题, 每题`.state` 1 MiB和Lean 2 MiB的Base64上界计算整个请求体的限额, 代理允许202 MiB即可覆盖接收上限. 本地测试可直接走回环HTTP.

构建发布包时, 在源码目录使用`build_console.py --out <归档路径> --submission-endpoint https://<发布方域名>/v1/submissions`. 地址写入发布包的`console/console-config.json`. 上传失败时, 该次运行的控制台可向同一接收地址重试, 沿用原提交编号.

新提交写入SQLite的`submissions`表, 保留完整原始JSON, 收件时间和`pending`状态. 首次接收返回HTTP 201, 同一内容重试返回HTTP 200和同一个提交编号. 请求头的编号由规范化JSON的SHA-256计算, 接收器重新核对整个提交及两份源文件的哈希再写入. SQL示例可在发布方服务器上查看待审元数据, 无需公开数据库文件.

```sql
SELECT submission_id, received_utc, status FROM submissions ORDER BY received_utc;
```

## 核验与发布

回执`pending`表示已经进入私有待审池. 内容哈希用于识别重复提交和检查文件一致性. 管理员可按回执编号取出原始提交, 对照锁定的题目和评分规则, 在独立隔离的核验环境中重新编译态定义, 运行固定目标Lean核验并复算能量与分数. 对实验设置和技术缺口还可核对协议, 预算, harness版本和特定题集. 接收器只存档, 候选文件的独立核验由管理员发起, 公共榜单也由管理员另行发布.

当前交付包含客户端和接收器. 公开部署所需的发布方域名, 托管账户和HTTPS接收地址仍需配置.
